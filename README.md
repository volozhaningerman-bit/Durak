# Durak RPG

Telegram Mini App: классический и RPG-режимы игры «Дурак» для 2–6 игроков.

## Режимы

### Классический
Настраиваемые правила:
- 2–6 игроков
- подкидной / переводной
- кто может подкидывать: все / крайние
- дополнительные параметры будут добавляться через единый объект настроек комнаты

### RPG
Всегда подкидной + переводной. Игрокам случайно выдаются уникальные классы.

1. **Козырник** — после обычной раздачи выбирает ровно одну козырную масть. Сервер находит карту этой масти в оставшейся колоде, переносит её вниз и делает открытой козырной картой.
2. **Переводчик** — до 2 раз за матч может перевести атаку любой своей картой, даже если достоинство не совпадает.
3. **Пятёрочник** — на него можно положить максимум 5 атакующих карт; после хода он добирает из колоды только до 5 карт вместо 6.
4. **Подкидчик** — при каждом подкидывании получает первый приоритет. После него подкидывает исходный атакующий, затем остальные допустимые игроки.
5. **Реверс** — может перевести атаку в обратном направлении. Такой перевод также разворачивает глобальное направление партии до следующего реверса.
6. **Джокер** — после обычной раздачи 6 карт получает дополнительную 7-ю карту-джокер. Джокер может побить любую карту. Если защитник успешно отбился, сыгранный Джокер уходит в биту. Если защитник в итоге забирает стол, Джокер возвращается ему в руку вместе с остальными картами и может быть использован снова.

## Архитектура

- `apps/web` — Telegram Mini App, React + TypeScript
- `apps/server` — authoritative game server, Node.js + WebSocket
- `packages/game-core` — чистая игровая логика и тесты
- PostgreSQL — профили, прогресс, история матчей, инвентарь
- WebSocket — realtime-синхронизация 2–6 игроков
- Telegram initData — авторизация с серверной проверкой

## Принципы

- Сервер является единственным источником истины.
- Клиент не решает, допустим ли ход.
- RPG-классы реализуются отдельными модификаторами правил.
- Игровая логика отделена от Telegram и UI, чтобы её можно было тестировать без запуска приложения.
- Темы интерфейса: светлая / тёмная. Telegram Fullscreen API используется для игрового режима на весь экран.

## Монетизация

Архитектура предусматривает Telegram Stars:
- косметика;
- эмоции/насмешки и броски предметов;
- расходники/способности комнаты через feature flags.

Игровые расходники будут отделены от рейтинговых правил, чтобы их можно было независимо включать/выключать для разных очередей.

## Рейтинг

Рейтинг меняется только в рейтинговых матчах. В каждой партии разыгрывается фиксированный пул **30 рейтинга**: дурак теряет 30, а победители делят эти 30 по порядку выхода. Чем раньше игрок избавился от карт, тем больше получает. Примеры: 2 игрока — +30 / −30; 3 игрока — +20, +10 / −30; 4 игрока — +15, +10, +5 / −30; 5 игроков — +12, +9, +6, +3 / −30; 6 игроков — +10, +8, +6, +4, +2 / −30. Нижняя граница рейтинга — 100; если у проигравшего осталось меньше 30 до границы, победители делят только фактически списанную сумму.

## Недавние игроки и приглашения

После совместной игры или входа в одну приватную комнату игроки автоматически попадают друг другу в «Недавние». Из приватной комнаты можно повторно позвать такого игрока: сервер проверяет, что контакт уже встречался с отправителем, и тестовый бот отправляет персональное сообщение с кнопкой входа. Повторные приглашения одному человеку ограничены коротким cooldown.

## Статус

Базовая архитектура и игровое ядро в разработке. Основные RPG-классы и их ограничения зафиксированы тестами.


## Production запуск на VPS

Для реального Telegram Mini App нужен домен, который указывает A/AAAA-записью на VPS, и открытые порты 80/443. HTTPS выдаёт Caddy автоматически.

1. Скопировать репозиторий на VPS.
2. Перейти в папку `deploy`.
3. Скопировать `.env.example` в `.env`.
4. Заполнить:
   - `DOMAIN` — домен без `https://`;
   - `BOT_TOKEN` — токен тестового бота из @BotFather;
   - `TELEGRAM_WEBHOOK_SECRET` — случайная строка для проверки webhook, например результат `openssl rand -hex 32`;
   - `POSTGRES_PASSWORD` — длинный случайный пароль.
5. Запустить:
   ```bash
   docker compose up -d --build
   ```
6. Проверить:
   ```bash
   WEBAPP_URL=https://your-domain.example npm run smoke
   ```

В production один Node.js-процесс отдаёт и Mini App, и API/WebSocket. PostgreSQL работает только во внутренней Docker-сети. Caddy принимает HTTPS и проксирует WebSocket автоматически.

### Привязка тестового Telegram-бота

После того как HTTPS-адрес уже открывается:

```bash
BOT_TOKEN="..." TELEGRAM_WEBHOOK_SECRET="..." WEBAPP_URL="https://your-domain.example" npm run configure:telegram
```

Скрипт проверит токен через Telegram Bot API, установит защищённый webhook, создаст кнопку **«Играть»** в меню бота и команды `/start` и `/play`. Команды отвечают сообщением с Web App-кнопкой, поэтому бот работает без отдельного polling-процесса.

Для ссылок-приглашений вида `https://t.me/BOT_USERNAME?startapp=room_ABC123` дополнительно открой @BotFather и включи для этого же бота **Main Mini App**, указав тот же `WEBAPP_URL`. После этого друг сможет нажать ссылку и автоматически попасть в нужную приватную комнату без ручного ввода кода.

Токен нельзя коммитить в GitHub. Он хранится только в `deploy/.env` или в переменных окружения сервера.

### Минимальная проверка перед тестовой игрой

- `https://DOMAIN/health` возвращает `ok: true`;
- `/api/config` показывает `telegramConfigured: true` и `databaseConfigured: true`;
- Mini App открывается из кнопки **«Играть»** внутри Telegram;
- два разных Telegram-аккаунта могут выбрать одинаковые параметры и попасть в одну комнату;
- после перезапуска/краткого обрыва сети игрок возвращается на своё место;
- результат партии появляется в профиле и истории, а рейтинговая партия меняет Elo.
